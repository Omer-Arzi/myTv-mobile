Status legend: `TODO` `IN_PROGRESS` `BLOCKED` `DONE`

This file is the live working record for merging the Library tab into Watchlist's WATCH LIST mode and adding a new System tab for manual status-scoped DB refreshes. Recorded as a lightweight idea 2026-08-02, promoted to an active task the same day. Updated continuously, not just at the end. Full plan (approved, superset of this file): `/Users/omerarzi/.claude/plans/wiggly-crunching-sutherland.md`.

## Task goals

1. Watchlist's WATCH LIST sub-mode becomes what `LibraryScreen.tsx` does today — browse every tracked series, filterable by `UserSeriesStatus` — replacing the standalone Library tab. UPCOMING sub-mode untouched.
2. Remove the standalone Library tab; Search takes its old bottom-nav slot.
3. Add a new System tab (Search's old slot) where the user manually triggers a DB refresh scoped to chosen show status(es), then clicks Fetch.
4. Server gains a status-scoped variant of the existing whole-library manual refresh.

## Decisions made (settled, not open)

- **Multi-select** status filter for the System tab's fetch — checkboxes, one Fetch covers all chosen statuses at once.
- Merged Watch List panel defaults to **WATCHING** on first open (not Library's old `CAUGHT_UP` default).
- **Skip** persisting which status(es) a job was scoped to for v1 (no `LibraryRefreshJob` schema migration now) — System tab shows only live generic progress. Revisit later as an additive migration if a real need shows up.

## Known constraints (must not be violated)

- The merged Watch List panel must stay a virtualized list (`SectionList`, bounded `windowSize`/`initialNumToRender`). `WatchListPanel.tsx` fixed two confirmed real-device production crashes by moving off a plain `ScrollView`+`.map()` — exactly the rendering shape `LibraryScreen.tsx` uses today. That shape must not be reintroduced.
- Server-side provider-facing loops always run sequentially, never parallel (`library-refresh-job.service.ts`'s `processJob` already does this and must stay this way) — a status filter only ever shrinks the candidate list feeding that same loop, never changes its concurrency model.
- Pure `*-logic.ts`/`*-helpers.ts` (no I/O, unit-tested without a DB) stay separated from `*.service.ts` I/O, matching the rest of this codebase.
